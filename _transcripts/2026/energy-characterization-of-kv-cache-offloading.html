3:53 So the KV cache lives in a fixed size pool on the GPU. Whatever is left after loading in the model weights is for the KV cache. As soon as our context windows start to get larger, maybe concurrent requests start to increase, that causes this pool to fill. And there's a certain point where the scheduler has no choice but to make room for more requests. And in order to do so, it needs to evict some of its current running requests. We have offloading off where the evicted request's cache state is simply dropped.

4:46 And when it's time to resume, the engine recomputes everything. So it reruns the entire prefill from scratch at peak power. With offloading on, the engine quietly copies the state out to host memory during the entire time the request is running. So when the request needs to get preempted, it'll transfer these requests over to the CPU via this bus. And when it comes time for the request to resume, we don't recompute everything. We'll simply reload these blocks that we previously copied over to the CPU. So both of these conditions still come during preemption. And the only difference is the cost of recovery. So we're already starting to build some intuition that on one hand, we have this round trip where we are copying over blocks and we are reloading them.
